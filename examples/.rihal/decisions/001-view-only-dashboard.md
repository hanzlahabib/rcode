# ADR 001 — View-Only Dashboard

**Status:** Accepted
**Date:** 2026-04-10
**Decider:** Waleed (CTO)

## Context

The module needs a UI to visualize project state: phases, progress, decisions, artifacts. Two approaches were considered: a full CRUD dashboard (with a database) or a view-only server that reads files directly.

## Decision

Build a view-only dashboard that reads `.rihal/` files and renders HTML. No database, no writes, no API endpoints beyond GET.

## Consequences

### Positive
- Zero fragility — cannot corrupt state via dashboard bugs
- Zero migrations — state schema = file structure
- Works offline
- Single Node.js file, no dependencies
- Git-native (state lives in the repo)

### Negative
- Users cannot edit state from the browser (must use workflows)
- Refresh-based (5s) instead of real-time push

### Neutral
- Requires running a separate process
- Uses port 7717 (configurable)

## Alternatives Considered

### Full CRUD with SQLite
- Rejected: adds dependency, migration headaches, state divergence from files
- When we'd reconsider: multi-user editing becomes a requirement

### Static HTML generated by a workflow
- Rejected: doesn't auto-refresh, users must manually regenerate
- When we'd reconsider: if we want to publish state to a static host

### VS Code extension
- Rejected: ties users to one editor
- When we'd reconsider: if adoption demands IDE-native experience
