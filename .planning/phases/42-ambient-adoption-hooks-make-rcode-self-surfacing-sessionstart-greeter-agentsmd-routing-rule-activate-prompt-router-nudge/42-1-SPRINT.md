## Sprint Goal

Add a "rcode Command Routing" rule block to the CLAUDE.md template that `rcode-tools.cjs generate-claude-md` writes to consumer projects, so the agent in any rcode-initialized project learns to check `do.md` for the right command before handling planning/exploration/audit work ad-hoc. The rule must REFERENCE `do.md` as the single source of truth and must NOT duplicate any keyword→command mapping. The block must be small (< 12 lines) and reviewable.

This sprint only modifies `rcode/bin/rcode-tools.cjs` (the `cmdGenerateClaudeMd` function). Nothing else changes.

**Discovery finding:** the only file rcode writes agent-facing instructions to in consumer projects is CLAUDE.md, generated by `rcode-tools.cjs generate-claude-md` (also invoked from `rcode/workflows/new-project-roadmap.md`). There is no standalone AGENTS.md template; no init step appends to an existing AGENTS.md. The routing rule must land in the CLAUDE.md template string inside `cmdGenerateClaudeMd` at `rcode/bin/rcode-tools.cjs:4487`.

### Story 42.1.02 — Add `## rcode Command Routing` rule block to CLAUDE.md template

<objective>
Edit the template string inside `cmdGenerateClaudeMd` in `rcode/bin/rcode-tools.cjs` to insert a `## rcode Command Routing` section. The block must:
- Tell the agent to check `do.md` for a matching intent → command before acting ad-hoc
- Name `rcode/workflows/do.md` as the single source of truth (exact path)
- NOT reproduce or inline any keyword→command table — only reference it
- Mention `/rcode-memory-update` as the fallback for work done outside rcode
- Fit in ≤ 12 lines of Markdown
- Be inserted just before `**This file is part of the project. Treat it as load-bearing.**`
</objective>

<action>
In `rcode/bin/rcode-tools.cjs`, inside the template literal in `cmdGenerateClaudeMd`, insert the following block just before the final `---\n\n**This file is part of the project. Treat it as load-bearing.**\``:

```
---

## rcode Command Routing

Before handling planning, exploration, auditing, refactoring, or multi-step build work ad-hoc, check whether a matching rcode command exists first.

**How to check:** read \`.rcode/workflows/do.md\` (installed by rcode) for the intent → command routing table — it is the single source of truth. Common cases: planning a phase → \`/rcode-plan\`, adding a phase → \`/rcode-add-phase\`, exploring/brainstorming → \`/rcode-brainstorm\`, auditing → \`/rcode-audit\`, executing a sprint → \`/rcode-execute\`, mapping the codebase → \`/rcode-map-codebase\`. Always consult \`do.md\` — never infer from memory alone, as the table changes with the release.

**Why:** rcode commands record outcomes in \`.rcode/state.json\` and \`.planning/\`. Work done ad-hoc creates silent state divergence. If you must proceed ad-hoc, run \`/rcode-memory-update\` afterward to keep long-term memory consistent.

```

IMPORTANT (template literal safety): The ` ``` ` that closes the illustrative code fence above is NOT part of the Markdown content to be inserted — it must NOT appear literally in the JavaScript template string. A raw triple-backtick would terminate the template literal and produce a syntax error in `rcode-tools.cjs`. Any backtick characters that ARE part of the inserted Markdown content must be escaped as `\`` (consistent with the surrounding template literal). The `node --check rcode/bin/rcode-tools.cjs` verify step will catch this immediately if a stray backtick breaks the template.
</action>
