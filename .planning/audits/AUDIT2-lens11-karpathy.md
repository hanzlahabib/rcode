## Findings

### Principle 1 — Think Before Coding
*Unclear assumptions, magic numbers without comment, hardcoded thresholds*

| File | Line | Description | Severity |
|------|------|-------------|----------|
| `rcode/bin/rcode-tools.cjs` | 4392 | `if (len > 300 && len <= 800)` in `classifyScope()`. A 300–800 character range is used to infer `'phase'` scope from input text when keyword matching fails. No comment explains why these bounds were chosen, where they were derived from, or what breaks outside them. A reader cannot verify or tune this heuristic. | **warn** |
| `cli/install.js` | 2700 | `{ timeout: 4000 }` on `execFile('npm', ['view', '...', 'version', '--json'])`. The 4,000 ms limit on the background update-check npm call has no explanatory comment. The intent (short enough to not block UX, long enough to succeed on slow networks) is guessable but not stated. Compare: `install.js:2519` explicitly comments "60s timeout — without it, a slow upstream URL hangs the install". | **info** |
| `rcode/bin/rcode-hooks.cjs` | 400 | `execSync('git log ...', { timeout: 3000 })` in `preCompact`. The 3,000 ms cap on git log during a hook is unexplained. No comment states why 3s was chosen (not 1s, not 10s). | **info** |
| `test/skill-description-budget.test.cjs` | 8 | Top-of-file docblock states: *"Today 30 of 105 skills exceed the budget — top offender is 449 chars."* The `BASELINE_OFFENDERS` constant on line 34 is `0` (all offenders trimmed), and the install catalog was condensed to **49** skills (commit `76b7ac4`, 2026-05-25). The docblock caption is a snapshot from 2026-04-30 and is now doubly stale: wrong count, wrong baseline, wrong offender. A reader auditing this test file will be misled. | **warn** |

### Principle 2 — Simplicity First
*Dead code, unused imports, speculative abstractions, over-engineered helpers*

| File | Line | Description | Severity |
|------|------|-------------|----------|
| `rcode/brain/sources.yaml` | 30, 43 | Two of three `sources[]` entries have `repo: "<PLACEHOLDER: github.com/rcode-om/???>"`. The file header says "Real URLs land as part of issue #162" but gives no date. Both placeholder sources are copied to `.rcode/brain/sources.yaml` and installed into every user's project. The `cmdBrain()` dispatcher gracefully skips them — but the sources represent intent, not function. Having two permanently-placeholder config entries shipped to all users is misleading and invites confusion without a clear deadline. | **warn** |
| `rcode/bin/rcode-tools.cjs` | 5119 | `cmdDocsAudit()` is described in its JSDoc as *"placeholder inventory of documentation gaps; non-fatal."* The function body is not a placeholder — it reads `documentation-requirements.csv` and returns gap data — but the JSDoc word "placeholder" signals either (a) the function body replaced a true stub and the comment was not updated, or (b) the function's scope was always intended to be larger. The label creates false uncertainty about whether the dispatch case is real. | **info** |

### Principle 3 — Surgical Changes
*Whitespace-only diffs, drive-by reformatting, unrelated edits bundled with primary change*

| File | Commit | Description | Severity |
|------|--------|-------------|----------|
| `rcode/bin/rcode-hooks.cjs` (and `.rcode/bin/rcode-hooks.cjs`) | `ece739c` | Commit `fix(hooks): use os.tmpdir() instead of hardcoded /tmp` bundled an unrelated observability regression: it **removed** a `console.error('[hook] git log failed:', err.message)` in `preCompact()` and replaced it with a silent `catch {}`. ### Principle 4 — Goal-Driven Execution
