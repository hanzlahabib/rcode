# Audit: Persona Skill False-Dispatch Sweep

**Scope:** Every skill under `rcode/skills/agents/` **except** `hanzla-engineer`, `yousef-backend`,
`haitham-frontend` (GH #1004, open) and `majlis-council` (fixed in `008647f`) — those four are
already-known instances of this bug class and are excluded per instructions.

**Bug class under test:** does the skill's `SKILL.md`/`description`/`references.md` claim or
imply that invoking it dispatches a real, isolated-context `Task`-tool subagent (or otherwise
does genuine multi-agent work), when what actually happens is inline persona roleplay in the
current session — with no `Task()` call, no isolation? Precedent: commit `008647f` found and
fixed this exact framing in `majlis-council/references.md` ("Real mode (default). Dispatches
actual subagents via the `Task` tool" while its own capability table marked every convene-mode
sub-skill "planned — not implemented").

**Method:** read every `SKILL.md` + `references.md` under `rcode/skills/agents/` (19 dirs in
scope); grepped for dispatch/subagent/Task(/isolated/multi-agent language; cross-referenced each
persona against `rcode/team.yaml` (`agents:` / `tactical_agents:` sections), the real subagent
definitions in `rcode/agents/*.md`, and actual `Task(subagent_type=...)` call sites in
`rcode/workflows/*.md` (primarily `council.md`, `lens-audit.md`, `correct-course.md`, `scan.md`,
`map-codebase.md`).

## Summary

- **1 confirmed gap, same class as majlis-council, unfixed:** `raees-orchestrator`. Its Overview/Output Format/Examples all narrate Raees actively dispatching, sequencing, and parallelising other agents ("Layla invoked first", "Dispatching Haitham directly"), while its own Capabilities table marks every dispatch mechanism (`DP`/`SQ`/`PL`/`HO`) `[planned — not yet implemented]`, and there is no `rcode-raees*` entry in `team.yaml`, `rcode/agents/`, or any `Task()` call in `rcode/workflows/*.md`. Needs the same treatment `008647f` gave majlis-council: correct the prose to say this is inline planning output only (a dispatch *plan*, not a dispatch *action*), and point users at whatever real mechanism (if any — currently none exists) does live routing.
- **1 borderline gap:** `hussain-sm`'s `ER` capability is labeled "Multi-agent review" but is backed by single-session Bob/Alice/Charlie roleplay (`rcode-retrospective/workflow.md`'s "Party mode protocol"), and — unlike every other council-roster persona — has no real `rcode-hussain-sm` Task-dispatchable twin anywhere (absent from `team.yaml`, `rcode/agents/`, and every workflow). Worth relabeling to avoid implying real multi-agent dispatch.
- **14 personas are clean**: they use the honest "This skill embodies X... archetype" framing (or explicit "No capabilities implemented yet — operates inline" framing for the not-yet-built ones), make no claims about spawning isolated Task subagents, and — where a real Task-dispatchable twin exists — it's genuinely wired into `council.md` (confirmed via `subagent_type="rcode-{id}"` call sites) or, for the 2 fully-implemented auditor agents (`rcode-i18n-auditor`, `rcode-deviation-analyzer`), into `lens-audit.md`/`correct-course.md`.
- **Adjacent finding (not a persona-skill false-claim, flagged for completeness):** `lens-audit.md` itself claims "Each lens delegates to its mapped primary skill via `Task()` subagent dispatch" but 3 of its 16 mapped primary skills (`rcode-dep-auditor` lens 5, `rcode-cross-platform-auditor` lens 10, `rcode-observability-auditor` lens 13) have no matching `Task(subagent_type=...)` call anywhere in the file — despite each having a real, working agent definition. This is a workflow-implementation gap, not a persona-skill documentation gap, and falls outside this audit's exact scope, but was directly surfaced by the "actually dispatched via Task()?" cross-reference and should be tracked separately.
- **Naming-consistency observation (not a bug):** `dalil-scout`'s persona ("Dalil") is honestly self-described as doing the work inline, but the real `Task`-dispatchable agent its own Capabilities table points to (via `rcode-scan`/`rcode-map-codebase`) is named `rcode-codebase-mapper`, not `rcode-dalil*` — no Arabic-persona framing carries through to the dispatchable agent. Not a false-dispatch claim (Dalil never claims to dispatch), but worth a naming-parity pass alongside any fix to the Raees/Hussain-SM findings above.
