## Verification Notes

**F1 / F2 — .gitignore stale block:**
Verified by reading `.gitignore` directly. Lines 13–19 are a hand-written pre-v4 block with `.rihal/` paths. Lines 46–73 are the `rcode-managed` block (delimited by `# ===== rcode-managed gitignore block =====`). Compared against `cli/install.js` lines 826–916: the current `ensureGitignoreBlock()` function writes `.rcode/bin/`, `.rcode/workflows/`, etc. — none of the `.rihal/` paths appear in the generated template. Conclusion: the repo's own `.gitignore` was written by an old v3 install and never refreshed with `rcode install`.

**F3 — .cursor/rules/rihal/ (182 files):**
Verified with `git ls-files .cursor/rules/rihal/ | wc -l` → 182 tracked files. Checked `cli/install.js` lines 530–553: current install writes to `path.join(target, '.cursor', 'rules', 'rcode', ...)`. Confirmed no `.cursor/rules/rcode/` directory exists: `ls .cursor/rules/` shows only `rihal`. Sample file `rihal/agents/rihal-ahmed.mdc` contains `@.rihal/references/response-style.md` — a path that no longer exists. On any OS, Cursor would fail to load these rule references.

**F4 — semantic.yaml rihal-tools scope:**
Verified at `.github/workflows/semantic.yaml:94`. Cross-referenced `CONTRIBUTING.md:342`: "legacy rihal-tools scope (pre-v4 rename); accepted for backward compatibility". The scope is intentionally retained but still represents rihal namespace residue in CI config.

**F5 — core-module.yaml _rihal-output:**
Verified `default: "_rihal-output"` at `.rcode/skills/rihal-init/resources/core-module.yaml:24`. Cross-referenced `rcode_init.py:218–219` which documents `_rcode-output` as the example value (mismatch). Test fixtures in `scripts/tests/test_rcode_init.py` also use `_rihal-output`. The skill creates output directories using this default — on every OS, a new install would create `_rihal-output/` rather than `_rcode-output/`.

**F6–F8 — Repo URL / package refs:**
Verified: all reference `github.com/hanzlahabib/rihal-code` which is the actual GitHub repo name (not yet renamed). F7 (nuke.js) is intentional backward-compat to uninstall the legacy `@hanzlahabib/rihal-code` package. These are INFO-level.

**Shell scripts — CLEAN:**
`scripts/dogfood-check.sh`, `scripts/sync-bin.sh`, `.claude/hooks/block-unregistered-phase-writes.sh`, `.claude/hooks/sync-bin-on-edit.sh` — zero rihal refs. `dogfood-check.sh` correctly uses `rcode-tools.cjs` and `.rcode/` paths throughout. No `cd .rihal/` patterns found. No `.rihal/` path hardcodes in `rcode/bin/` or `.rcode/bin/` libraries.

**Windows path joins — CLEAN:**
No `'/' + 'rihal'` string concatenation or `path.join(..., 'rihal', ...)` patterns found in live scripts. The `cli/install.js` uses `path.join()` for all `.cursor/rules/rcode/` paths.

## Recommended Actions

1. **[Critical] Re-run `rcode install` on this repo** — this will rewrite `.gitignore`'s managed block from `.rihal/` to `.rcode/` paths and regenerate `.cursor/rules/rcode/` to replace `.cursor/rules/rihal/`. The install.js code is already correct; only the repo's own installed artifacts are stale.

2. **[Critical] Delete `.cursor/rules/rihal/`** from git tracking after re-install generates `.cursor/rules/rcode/`. Cursor users on any OS will silently get broken rule references until this is done.

3. **[Warn] Remove lines 13–19 of `.gitignore`** (the pre-v4 hand-written block) — they are superseded by the managed block and ignore paths that no longer exist (`.rihal/` is gone).

4. **[Warn] Rename `_rihal-output` → `_rcode-output`** in `.rcode/skills/rihal-init/resources/core-module.yaml:24`, `SKILL.md`, and the test fixtures in `scripts/tests/test_rcode_init.py`.

5. **[Warn] Consider removing `rihal-tools` from `semantic.yaml`** scope list once the backward-compat window closes — or add an explicit comment that it will be removed in vX.Y.
